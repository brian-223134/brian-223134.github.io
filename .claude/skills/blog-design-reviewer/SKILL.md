# Blog Design Reviewer

## 목적
현재 Jekyll 블로그의 디자인 관련 파일을 탐색하고, 문제를 진단하고, 개선 방향을 제안하고, 필요하면 실제 수정까지 수행한다.

이 스킬은 아래 요청에 사용한다.

- 디자인 상태 점검
- UI/UX 개선 조언
- 색상, 폰트, 간격, 가독성 조정
- 헤더, 홈 화면, 사이드바, 포스트 목록 카드, 푸터 구조 수정
- Minimal Mistakes 테마 기반 화면을 프로젝트 스타일에 맞게 다듬는 작업

## 이 저장소에서 우선 확인할 파일

디자인 요청이 들어오면 아래 경로를 우선 탐색한다.

### 1. 전역 테마 설정

- `_config.yml`
  - `minimal_mistakes_skin`
  - 사이트 제목, 설명, author, footer, comments theme 등 전역 UI 관련 설정 확인

### 2. CSS 진입점

- `assets/css/main.scss`
  - 실제 커스텀 스타일 추가의 기본 진입점
  - 폰트 import, 커스텀 오버라이드, 추가 스타일 작성 위치로 우선 고려

### 3. 스킨 색상 변수

- `_sass/minimal-mistakes/skins/_plum.scss`
  - 현재 사용 중인 스킨의 색상 변수 정의 위치
  - 색상 체계 자체를 바꾸려면 여기 확인 필요

주의:

- `_sass/` 아래 파일을 수정하기 전에는 반드시 사용자에게 먼저 확인을 요청한다.
- 단순한 스타일 조정은 가능하면 `assets/css/main.scss`에서 오버라이드로 해결한다.

### 4. 구조와 레이아웃

- `index.html`
  - 홈 화면이 어떤 layout과 sidebar를 쓰는지 확인
- `_layouts/home.html`
  - 홈 화면의 최근 포스트 목록 구조 확인
- `_layouts/default.html`
  - 사이트 전역 wrapper, meta theme-color 등 공통 구조 확인

### 5. 공통 UI 조각

- `_includes/masthead.html`
  - 상단 내비게이션, 사이트 제목, 메뉴 구조
- `_includes/sidebar.html`
  - 사이드바 렌더링 구조
- `_includes/author-profile.html`
  - 프로필 카드, 아바타, 링크 목록 구성
- `_includes/archive-single.html`
  - 포스트 목록 카드/리스트의 제목, excerpt, teaser 구조
- `_includes/footer.html`
  - 푸터 링크 및 카피 문구 구조

### 6. 이미지 자산

- `assets/images/`
  - 프로필 이미지, 파비콘, 포스트 관련 시각 자산 위치 확인

## 요청 유형 분류

사용자 요청을 아래 중 하나로 분류한다.

### A. 점검 중심

예시:

- "디자인 어떤지 봐줘"
- "가독성 문제 있는지 확인해줘"
- "지금 블로그가 어디가 어색한지 말해줘"

동작:

- 관련 파일을 읽고 현재 구조를 분석
- 문제점, 개선 포인트, 우선순위를 정리
- 실제 수정이 포함되지 않았다면 우선 코드 변경 없이 조언만 제공

### B. 제한된 개선 요청

예시:

- "헤더 좀 더 깔끔하게 바꿔줘"
- "사이드바 간격 조정해줘"
- "폰트나 색상 좀 다듬어줘"

동작:

- 영향을 받는 파일 범위를 좁힌다
- 가능하면 `assets/css/main.scss`와 레이아웃/인클루드 수정으로 해결한다
- 모바일과 데스크톱 둘 다 고려해서 변경한다

### C. 구조 변경 또는 리디자인

예시:

- "홈 화면 레이아웃 바꿔줘"
- "Minimal Mistakes 느낌을 줄이고 싶어"
- "컬러 시스템 자체를 바꾸고 싶어"

동작:

- 현재 구조와 영향 범위를 먼저 설명
- `_sass/` 수정이 필요한지 판단
- `_sass/` 수정이 필요하면 사용자 확인을 받은 뒤 진행

## 작업 원칙

### 1. 먼저 읽고, 그 다음 바꾼다

디자인 수정 전에 반드시 현재 레이아웃, 스타일, 자산 구조를 먼저 읽는다.

### 2. 작은 오버라이드부터 시도한다

가능하면 아래 순서로 접근한다.

1. `assets/css/main.scss` 오버라이드
2. `_includes/` 또는 `_layouts/` 구조 조정
3. 필요 시 `_config.yml` 설정 조정
4. 정말 필요할 때만 `_sass/` 수정

### 3. `_sass/` 수정은 사용자 확인 후

이 저장소 규칙상 `_sass/` 파일 수정은 사전 확인이 필요하다.

### 4. 기존 테마 구조를 불필요하게 깨지 않는다

Minimal Mistakes의 기본 구조를 완전히 뒤엎지 말고, 사용자의 목적이 분명할 때만 큰 구조 변경을 한다.

### 5. 생성 산출물은 직접 수정하지 않는다

가능하면 아래 파일은 직접 수정하지 않는다.

- `assets/js/main.min.js`

이 파일은 배포 대상 산출물에 가깝기 때문에, 필요한 경우 소스 레벨에서 해결한다.

## 디자인 점검 체크리스트

### 시각 스타일

- 색상 대비가 충분한지
- 링크와 일반 텍스트가 구분되는지
- 강조색 사용이 일관적인지
- 코드블록, 인용문, 표가 읽기 쉬운지

### 타이포그래피

- 제목과 본문 위계가 명확한지
- 본문 line-height와 폭이 읽기 편한지
- 한글 본문에 적절한 폰트 조합인지
- 제목 폰트와 본문 폰트의 성격이 지나치게 충돌하지 않는지

### 레이아웃

- 헤더 메뉴가 복잡하지 않은지
- 사이드바 정보량이 과하지 않은지
- 포스트 목록에서 제목, 날짜, excerpt가 자연스럽게 읽히는지
- 모바일에서 줄바꿈과 간격이 깨지지 않는지

### 블로그 맥락 적합성

- 논문/강의/인턴 기록 중심 블로그에 맞는 정보 밀도인지
- 장식보다 가독성이 우선되어 있는지
- 시리즈형 글 목록이 탐색하기 쉬운지

## 출력 형식

### 점검만 요청받은 경우

```text
디자인 점검 결과

문제점
- ...
- ...

개선 제안
- ...
- ...

우선순위
1. ...
2. ...
```

### 수정까지 요청받은 경우

```text
수정 계획
- 어떤 파일을 왜 수정할지 설명

수정 내용
- ...

영향 범위
- 헤더
- 홈 화면 포스트 목록
- 사이드바
```

## 트리거 예시

아래 요청에서는 반드시 이 스킬을 사용한다.

- "블로그 디자인 확인해줘"
- "디자인 조언해줘"
- "헤더 레이아웃 손봐줘"
- "사이드바 더 깔끔하게 바꿔줘"
- "폰트나 색상 바꿔줘"
- "홈 화면 좀 더 보기 좋게 수정해줘"
- "가독성 개선해줘"
- "Minimal Mistakes 느낌을 덜 나게 조정해줘"

## 비적용 범위

아래 요청은 이 스킬의 주 목적이 아니다.

- 포스트 내용 작성 또는 요약
- front matter 검수
- 카테고리/퍼머링크 점검
- 일반적인 기능 버그 수정

이 경우에는 다른 스킬이나 일반 코드 수정 흐름을 사용한다.
